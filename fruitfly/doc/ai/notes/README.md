# Notes

Plain-language explanations of the code. Because the code is kept **comment-light** (see
the working style in `../FOUNDATIONS.md`), these notes carry the "why" — the intuition,
the reasoning behind each parameter, and the mapping from concept to implementation.

## Convention

- One note per concept / code unit (e.g. `lif-neuron.md` explains the `LIF` class).
- Notes are written for *understanding*, not as API docs. Analogies and derivations belong here.
- When code changes, update its note.
