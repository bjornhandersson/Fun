# Plan 0009 — Unite: a fly that flies to the banana in 2.5D (+ a real 3D view)

**Status:** Not started — chosen with the user. Both halves of flight are built and honest but
SEPARATE: horizontal (the 2D `Fly` — seek/avoid/memory) and vertical (`FlyingBody` — wingbeat lift,
hover reflex, climb-to-food). This unites them into one creature and shows it in a Godot **3D**
scene. Build order: the unified creature **headless first**, then the 3D view (the same
isolate-then-visualise path used throughout).
**Goal:** One creature that approaches the banana in **X/Y** (existing chemotaxis + wall-avoidance +
memory) while **climbing to its height** on a self-generated wingbeat (existing lift + hover +
vertical chemotaxis), and **eats it in 3D** — watchable as a fly flying through space.

## Why now

Everything points here. The 2D fly seeks a banana on a plane; the flying body seeks a height and
holds itself up. The banana is the shared goal — it just needs a *height*. Uniting is mostly
*composition* of two things we already trust, and it finally earns the **3D view** the user wanted
from the start (ADR 0004's eventual dual-view, now in 3D).

## The honest simplification (state it plainly)

In this rung, **forward** locomotion stays the 2D "wings-as-effectors" Braitenberg abstraction (same
as today's fly), while **lift / altitude** is the honest self-generated wingbeat. The thing that
physically unifies them — the body **pitching** so one wing-force vector splits into lift + thrust —
is the *next* rung (deferred, documented). So this is no *less* honest than the current 2D fly; it
adds an honest vertical axis on top. We say so in the code and the view, and we don't pretend the
forward thrust comes from the beat yet.

## Approach — composition, leave the proven parts untouched

- **`Fly` gains an OPT-IN vertical layer.** A `Fly` built in 3D mode owns a `FlyingBody` for its
  altitude and tells it to `SeekAltitude(bananaHeight)` each step; a `Fly` built in 2D mode (Play 6)
  is byte-for-byte unchanged. The proven horizontal brain/body is not touched.
- **The banana gains a height.** `World` keeps its 2D smell field and walls (horizontal) and adds a
  banana **height** (respawns at a random height too). Eating becomes **3D proximity** — near in X/Y
  *and* near in height.
- **The 3D view is a pure viewer.** A Godot `Node3D` scene reads the creature's 3D position +
  heading and places meshes (fly, banana, ground, walls). No brain/body logic in the view (ADR 0005).

## Steps (tiny pieces — assistant writes, one at a time)

- [ ] **World: the banana gets a height** — a `BananaHeight` that respawns randomly with it, and a
      3D-aware eat (`TryEat` considers altitude). 2D callers (Play 6) keep working.
- [ ] **Fly: opt-in vertical layer** — compose a `FlyingBody`, `SeekAltitude(world.BananaHeight)`,
      advance it each step, expose `Altitude`; eat when close in 3D. Prove headless: the fly reaches
      the banana in X/Y **and** in height, repeatedly (a `FlyHeadlessCheck`-style 3D assertion).
- [ ] **Godot 3D view** — a `Node3D` scene: ground plane, the four walls, the banana as a sphere at
      its 3D spot, the fly as a small mesh at its position + heading + altitude, a camera. Step the
      creature, place the meshes. Built up in sub-pieces (static scene → moving fly → polish).
- [ ] **(Optional) brain/altitude HUD** — a 2D overlay on the 3D view showing the wingbeat, lift,
      and the vertical/ horizontal senses, so the thinking stays visible.
- [ ] **Docs:** update this plan, [[0006]], [[0008]], and the FOUNDATIONS index as it lands.

## Open questions to resolve with the user (when we hit them)

- **Coupling.** Keep horizontal and vertical seeking fully independent (simplest), or couple them
  (e.g. ease off forward speed while still far below the banana's height)? Start independent.
- **3D view scope.** Fixed camera vs. follow-cam; how much fly detail (a body + flapping wings vs. a
  simple arrow); do walls/floor get textures or stay flat-shaded? Start minimal and flat.
- **Where the unified creature lives.** Extend `Fly` (recommended — composition, opt-in) vs. a new
  `FlyingFly` type. Extending keeps one fly and avoids duplication.

## Done when

The fly **flies to the banana through 3D space** — seeking it horizontally while climbing to its
height on its own wingbeat — and eats it, watchable in a Godot 3D scene. The user can explain which
parts are honest wingbeat-flight (lift, altitude-hold, vertical seeking) and which are still the 2D
abstraction (forward thrust), and why **pitch** is the next step to make forward flight true.
